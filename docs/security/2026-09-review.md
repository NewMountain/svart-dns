# Security review, September 2026 (pre open-source)

Three adversarial reviewers (DNS protocol; auth + HTTP API; sync + SQL + supply
chain) against commit 72d6b60. "Proven" means a PoC test reproduced it against
the real code; "inferred" means read from code only. PoC tests live outside the
repo (scratchpad copies `sec-dns/`, `sec-api/`, `sec-sync/`) and are ported into
the suite as regression tests when each item is fixed.

Finding descriptions preserve the original review against `72d6b60`. The status
column includes subsequent fixes; original severity and reproduction claims are
not rewritten as if the current source still had those defects.

## Follow-up verification — 2026-09-29

The complete strict verification and offline Go gates pass at `e6208c3`; the
real browser E2E passes at `a9185df`, whose application behavior is unchanged
through that verification revision. Current follow-up behavior is covered by:

- [Checkpoint contracts](../../checkpoint_contract_test.go) and

  SQL-side reconstruction, pagination and failure behavior.
- [Refresh failure tests](../../autorefresh_errors_test.go): database failures
  are reported, retries back off, and manual retry resets the backoff.

- [Logging durability](../logging-durability.md): bounded asynchronous admission,

- Generated request/response schemas and clients are checked by `make check-api`;
  frontend consumers validate responses at their API boundary. React Router is
  now on version 7. Dependency and native-library limitations remain in
  [dependency provenance](dependency-provenance.md).

These are component verification claims. Final rollout and its live operational
checks are tracked separately from this dated security review.

## Fix notes: auth and HTTP API (A1–A4, A6–A12, S4)

Operator-visible changes:

- Everyone must log in again once: the old HMAC cookies are not sessions.
  Sessions are node-local, so logging in on Blue does not log you in on Red.
- Browser mutations must be same-origin and send `Content-Type:
  application/json`. Scripts should authenticate with `X-Api-Key`, which is
  exempt from both checks (curl with `-d` keeps working).
- Private-network list URLs (a list server on the LAN) need
  `ALLOW_PRIVATE_LIST_URLS=true`. `HTTP(S)_PROXY` is not used for list
  fetches. Lists over `LIST_MAX_DOWNLOAD_BYTES` (256 MiB) or
  `LIST_MAX_LINES` (5M) fail to refresh and keep their previous version.
- Out-of-range `limit`/`offset`/`buckets` answer 400 instead of silently
  returning the default page; the query-log page limit is now 5,000.
- `ADMIN_ALLOWED_HOSTS` is optional hardening; unset allows every Host.

Decisions:

- CSRF is implemented by hand instead of with Go 1.25's
  `http.CrossOriginProtection`, which keeps the module on Go 1.24 and adds
  the JSON Content-Type requirement in the same place.
- The session cookie is `SameSite=Strict`; the SPA only issues same-origin
  fetches, so a navigation from another site loads the public shell whose
  own fetches then carry the cookie.
- Session tokens are random 256-bit values, not UUIDv7 (an unguessable
  secret must not embed structure). No user agent is stored.
- Readonly callers see list and upstream URLs with userinfo, query and
  fragment replaced by `REDACTED`; path segments (e.g. a DoH profile ID)
  stay visible.
- The vendored RapiDoc fetched Open Sans from fonts.gstatic.com on every
  /docs visit; `load-fonts="false"` now prevents the request.

The original review left follow-ups for schema generation, checkpoint
reconstruction, swallowed database errors, refresh retry backoff, bounded JSON
decoding and React Router 7. Those changes are now integrated and checked by
the tests listed above. The legacy `session_secret` setting remains preserved
for database compatibility, excluded from export/sync and unused by the random
server-side session mechanism; deleting historical operator state is unnecessary.

API-token verification now shares the four-slot login bcrypt cap and has a
four-per-second cold-request admission window. SQLite rows close before bcrypt.
The HTTP flood regression checks 429 responses, cached-token availability,
revocation and concurrent DNS/database responsiveness (DD-009).

## Original review: checked and found safe

Role matrix (no mutation reachable readonly/unauthenticated; HEAD safe); first-run
with no users is locked (401/503); cookie HMAC constant-time; API tokens 256-bit,
cache cleared on revoke; secrets never exported/imported; all `fmt.Sprintf` SQL
uses constants or placeholders; embedded FS rejects `..`; no
`dangerouslySetInnerHTML`/eval/browser-stored tokens; pairing handshake
(128-bit one-time codes, domain-separated HMAC proofs); gossip bounded by the
peer allowlist; sync TLS verification; sync payload caps; CI workflows free of
untrusted interpolation; malformed-packet handling (miekg); blocked replies
(NXDOMAIN + SOA); matchWildcard is linear.
